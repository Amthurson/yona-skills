# 企业商品发布到官网

仅在用户要求上架、更新或撤回官网商品时使用本流程。用户授权一批明确商品公开发布后，在同一范围内继续执行，不逐件重复询问。普通供应商/商品入库仍按企业业务流程完成，不默认公开。

## 入口与连接

- `/library/` 是登录后、受权限约束的企业产品库；`/products/` 是官网公开商品目录。两者分别验收。
- 需要企业 MCP 的 `enterprise_product_publication_preview`、`enterprise_product_publish`、`enterprise_product_withdraw`。工具缺失时先查客户端版本；服务不兼容或无 `yona:product-library:publish` 权限时由管理员升级或开通，不能用 Skill 更新代替。
- 商品维护 ACL 与发布权限同时生效。每人使用本人会话，不复制管理员凭据，不通过 SQL 或修改租户绕过权限。

## 上架 / 更新

1. 从正式入库回执定位商品。先调用发布预览，核对内部编号、当前字段、关联 SKU、主图哈希和已有发布状态。只有候选或供应商草稿时，先完成企业入库。
2. 以返回的可公开字段为边界。保留完整属性、单位、编号、共用页面/SKU范围及待核实说明。报价、客户、内部联系方式、经办人和原件不能混入公开属性或译文。供应商仍是内部草稿不等于已获得厂家公开展示资格。
3. 为 `en`、`pt-BR`、`es` 准备忠实译文。`translations` 按语言分组，使用 `product_group`（商品名）、`description`（别名/描述）、`spec_text`（规格/完整属性）、`standard_text`（SKU与来源声明/待核实说明）。商品名、规格属性及SKU说明均需完整；保留前导零、原单位和“不确定/商家声明”，不把翻译写成已核实适配结论。中文原始字段保留。
4. 确认已有商家/目录主图；共用主图的范围说明必须保留。没有主图或授权/对应关系不明时暂停该商品的公开操作，继续其他明确商品，不找相似图代替。
5. 调用 `enterprise_product_publish`，传 `product_id`、当前预览的 `review_digest`、`review_note` 和完整 `translations`。审核说明记录用户指定范围及资料依据，不写密码或内部客户资料。服务重新校验当前源事实与官网版本；冲突后重新读取并合并，不强制覆盖。
6. 回读发布预览的 `publication`。`published` 表示发布意向；`pending`/`failed` 仍未完成，`delivered` 表示版本已送达，随后还要验收实际官网。保留 `partId`、内部商品编号、`releaseVersion` 和实际状态。重复请求先回读，按同一来源/商品复用，不新建替代商品。

未知响应先查状态。按任务允许时间等待；一轮约5分钟仍未完成时保存回执并报告排队/失败原因，不能反复创建发布或把本地测试说成线上成功。

## 官网实际验收

在客户实际官网 `/products/` 入口搜索完整 SKU、品牌、不在品名中的原属性、品牌+属性、规格+属性，以及正确属性+错误SKU反例。记录查询词、数量和同一内部商品编号。打开详情，核对规格、属性、SKU声明和真实主图；必要时比对图片SHA-256。检查中文、英文、巴葡、西语详情及来源待核实说明。

公司 MCP、企业 `/library/` 与官网 `/products/` 分别报告。只有官网实际请求通过才标官网可用；没有访问条件就留待验，不用企业库命中或模拟数据代替。现有其他公开商品应保持可查。

## 撤回

用户明确要求撤回时，重新读取当前发布预览，用新 `review_digest` 和撤回依据调用 `enterprise_product_withdraw`。等待送达后检查官网不再返回该商品。企业档案、供应商/SKU关系和报价历史保留；不要删除正式产品来实现官网下架。重新上架复用同一企业商品和官网编号。

## 用户可复制的批量指令

> 使用 yona-supplier-catalog，将我指定的这批已确认商品发布到官网。先核对每件的公开字段、完整属性、SKU和主图范围，补齐忠实的英文、巴葡和西语译文；保留商家声明及待核实说明。我的本次指令授权这批商品公开上架，不逐条重复询问。缺图、来源/身份冲突或公开范围不明确的条目单列待办，继续其余明确条目。通过发布预览和正式工具上架，保存版本回执；分别报告企业入库、送达状态和实际官网搜索、详情、图片验收。不要公开内部报价、客户或联系方式，不重复建商品。
