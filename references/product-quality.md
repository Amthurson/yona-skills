# 完整属性到搜索

读取完整属性表、SKU选项、包装/重量和主图范围，记录实际读取的源属性行数。PDF/Excel保留页码或工作表行号；网页保留商品链接和具体SKU。缺页/折叠区没有读完时不能报完整。

| 来源信息 | 业务位置 |
|---|---|
| 品名、品牌、型号、类目、单位 | `name,brand,model,category,unit` |
| 供方SKU、OE、供方声明适配 | `supplierSku,oeNumbers,vehicleFitment`，编号按文本 |
| 规格与所有商品属性 | `specification`；已确认兼容服务可另用 `attributes` |
| 有来源的其他名称/语言名称 | `aliases`，不编造技术同义词 |
| 报价、币种、数量、有效期 | 候选报价与历史，不进入公共属性 |
| 供方联系、询盘客户 | 受限字段，不进入检索文本 |
| 主图 | 真实原图、SHA、来源与SKU/共用范围 |

“商家标题含半热熔”只能保留为商家声明。多型号共用页面须保留该属性对指定SKU待确认，不将标题当作性能或适配结论。

## 整理校验

按 `assets/product-evidence-template.json` 保存提取结果。该示例全部为合成资料，不能入业务库。`source_attribute_count`记录实际读取的行数，`attribute_inventory`保留各行值、范围和来源。

```powershell
python <Skill目录>/scripts/prepare_product.py <资料工作目录>/evidence.json --capability baseline --output <资料工作目录>/product-plan.json
```

`baseline`保留原规格并追加完整属性，最多2000个UTF-16字符。`attributes-v1`仅用于当前详情已返回该字段、或管理员提供已验收接口版本的服务，独立属性最多4000个UTF-16字符；不是试错开关。

校验拒绝行数不符、非文本编号、超长属性和公共属性中的联系方式/客户信息。未知空值进入未完成清单。它保证已提取清单在编码时不丢弃，不能证明原网页/PDF已完整读取。

使用输出的 `product_fields` 调用MCP。新候选再合并真实报价字段；维护商品时先读当前编辑快照，用版本和完整商品字段保存，不向维护接口写报价。接口拒绝新字段时先回读状态，再使用已验证兼容方案，不重新创建商品。

## 搜索验收

1. 按返回ID回读，逐项对照源属性、范围说明、版本、主图SHA和SKU关联；未确认候选不算商品。
2. 公司MCP检索源SKU及至少两个不在品名内的属性，保存实际查询、结果数和商品编号。
3. 验证品牌+属性、规格+属性；正确属性+错误SKU应排除该商品。不虚构缺少来源的属性来凑用例。
4. 等待已有公司到巴西同步，再在实际巴西入口重做查询并打开详情；核对内部商品编号，两端数值ID可以不同。
5. 权限错误、索引未就绪、未同步、零命中分别报告。没有前端访问条件则待验。RAGFlow文档检索另验，不与ES混称。

`assets/search-cases-template.csv`只是验收表头，不是预先通过的结果。
